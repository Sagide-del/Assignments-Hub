# Illustrated recall cards

Native recall cards use an original landscape revision-card design: subject/grade header, topic, cue, illustration, mnemonic, linked facts and explanatory note. The student's numbered/covered view hides diagram names and study notes; reveal shows them. Retrieval questions remain separate, with individual answer checks and the existing self-reported review actions. The card deck presents one readable card at a time. Existing uploaded PDF resources remain accessible.

Illustrations are generated from bounded JSON metadata in the existing `MnemonicCard.content` field. There is no schema migration, manual asset upload or additional image-provider request per generated card. Both curriculum-outcome and source-based generation ask for that metadata in their existing AI request. The server validates and retains only supported visual properties; arbitrary SVG, HTML and remote image URLs are not accepted as visual payloads.

Available visuals are an authored-template diagram (heart, lungs, plant cell, closed electrical circuit), labelled concept map, ordered process, comparison, timeline or validated proper-fraction model. The heart asset is an original generated illustration stored in `frontend/public/recall-illustrations/heart-cutaway.png`; the other scientific diagrams are original SVG schematics in `RecallIllustration.tsx`. Scientific diagrams use fixed authored callouts rather than model-invented coordinates. All generated content and choice of diagram still need editorial accuracy review. A small diagram library is not a claim of a bespoke anatomical illustration for every possible curriculum outcome.

Older text cards remain stored unchanged. The frontend uses narrowly matched science-topic diagrams where applicable, and otherwise builds a concept map from the card's existing facts. It does not substitute an unrelated anatomy image for an English literary reference to the heart. Admin review uses the same study-card component and supports changing the visual style, diagram, caption and labels before saving an unpublished draft. Old content does not need paid regeneration just to use the new presentation.

Print / Save PDF clones only the revealed study sheet into an isolated print document, loads its styles and illustration, and invokes the browser print dialog. It excludes surrounding navigation and other learner content. Print CSS uses landscape A4; long legacy content can require additional paper. Local review buttons suggest intervals but do not claim a persisted spaced-repetition schedule or measured mastery.

Checks: backend recall validation and card-service tests; frontend `npm run test:recall`; browser coverage for legacy cards, answer reveal, deck navigation, PDF resources, isolated printing, admin metadata editing and mobile widths. The content API advertises `illustratedRecallCardsVersion: 1`; frontend deployment waits for that capability so visual metadata is not silently dropped by an older backend validator.
