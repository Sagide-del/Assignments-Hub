# AI Content Pipeline

This module stages AI-generated educational content outside the existing
`Assignment`, `Question`, and `Submission` records. No generated assignment
can enter the learning system without validation, review, approval, and an
explicit publish request.

## Safety flow

```text
PDF -> AiExtractedContent
    -> AiGenerationJob
    -> AiContentArtifact (GENERATED)
    -> validate (IN_REVIEW)
    -> approve (APPROVED)
    -> existing AssignmentsService (draft)
    -> explicit publish (PUBLISHED)
```

- Every record is scoped by `schoolId`.
- Teachers can only manage artifacts generated by their own account.
- Students cannot read AI artifacts.
- Source PDFs are stored privately under `ai-source/{schoolId}/` in S3.
- Provider calls use the existing DeepSeek-to-Claude fallback router and
  existing `AiUsageLog` accounting.
- Idempotency keys are unique per school.
- Assignment creation and publishing go through `AssignmentsService`.
- Correct answers remain protected by the existing student assignment
  response filtering.

## Feature gates

All access requires both the global and feature-specific environment flags:

```text
AI_FEATURES_ENABLED=true
AI_ASSIGNMENT_DRAFTS_ENABLED=true
```

The school must also have an enabled `AiFeatureConfig`, an active or trial
subscription, and a permitted staff role. New school configurations default
to disabled and preview-only.

Set `AI_FEATURES_ENABLED=false` to disable the complete pipeline immediately.
The additive AI tables may remain in place; existing learning flows do not
read them.

## Deployment

1. Run `npm run prisma:deploy`.
2. Confirm `AWS_REGION` and `AWS_S3_BUCKET` point to private storage.
3. Configure `DEEPSEEK_API_KEY` and optional Claude fallback credentials.
4. Keep all AI feature flags off.
5. Deploy the backend and verify its health.
6. Enable a school configuration only after Phase 3 authenticated endpoints
   and workers have been deployed and tested.

## Worker boundary

Phase 2 exposes idempotent worker entry points:

- `AiExtractionService.processExtraction(extractionId)`
- `AiTopicAssignmentService.processGeneration(jobId)`

Phase 5 can invoke these from BullMQ. The queue processors should contain no
provider or learning-system business logic.

This phase intentionally adds no HTTP controller. The services are not
externally reachable until the authenticated, role-protected Phase 3 API is
implemented.
